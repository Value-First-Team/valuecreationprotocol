This repo has no version number. The live site is the Next.js app in `next/`. The `package.json` at the repo root belonged to the retired Astro build; it carried `0.1.0` and nothing read it, so that field was dropped on 2026-09-28 in the commit that adopted this file (the root lockfile was `pnpm-lock.yaml`, which records no project version), and the whole retired Astro build left the repo root later that day (`dc26030`). `next/package.json` still says `0.1.0`, and the checker never reads it. `L4-orchestration/scripts/repo-changelog-lint.mjs` therefore runs this file in no-version mode. Oracle owns the site's practice; Showcase owns the code.

**An entry is a production deploy that changes what a visitor sees or can do** on valuecreationprotocol.com: a new page, a copy change a person would notice, canon refreshed from the brain (`npm run canon:refresh` rewrites the documents under `next/src/content/canon`), a broken thing fixed, a layout or theme change, a redirect added or moved. It is headed `## <date> — deploy <sha>`, where the sha is the commit that carries the change and the date is the UTC date of its production deploy. Production is the Vercel project `valuecreationprotocol`, which builds `next/` from `main`; it serves that commit or a later one. Newest at the bottom. The reader here is a visitor, so **Consumer action** says what a visitor has to do: usually nothing, and an old address that now redirects is the common exception. **Owner** is the seat that built the change.

**A shared-package pin move gets an entry too.** The pages are drawn by the shared `@vf` packages, so moving a pin is how their changes reach visitors. Say what a visitor now sees differently; if the move changes nothing a visitor would notice, say that in one line, as the `72ead37` entry below does.

**What the check enforces.** Run `npm run check` in `next/` before you push. It runs `npm run assert:changelog` first, then the canon drift gate, then `next typegen` and the typecheck. `next typegen` writes `next/next-env.d.ts` and the route types (both gitignored, and both written by `next dev` and `next build` too), so the typecheck passes on a fresh clone with no build first. `assert:changelog` runs `repo-changelog-lint.mjs` through `repo-changelog-lint-run.mjs` at the repo root, a launcher generated by `--print-runner`. Regenerate it; never hand-edit it. The check fails in three cases:
- this file is missing;
- any entry lacks one of the four fields;
- a commit after the newest entry's cited commit (and after `72ead37`, where this check was adopted) touches `next/src`, `next/public`, `next/next.config.ts`, `next/vercel.json`, `next/tailwind.config.ts`, `next/postcss.config.cjs` or `next/package-lock.json` with no newer entry.

`next/package.json` is not on that list, so editing a script there does not demand an entry; a dependency change moves `next/package-lock.json`, which is on it. `next/scripts` (the canon drift gate) runs only on a developer's machine, and the canon it writes lands in `next/src`, which is on the list. The retired Astro build that used to sit at the repo root was deleted on 2026-09-28 (`dc26030`); `next/` is the only tree. The check sees commits only, never uncommitted edits: commit the change, add its entry citing that commit, then push. A push made from a Claude Code session on the MainBrain station runs the same check (`.claude/hooks/repo-changelog-push-gate.mjs`) and is refused when it fails. It is not part of the Vercel build. Outside a MainBrain checkout the launcher prints SKIPPED and checks nothing; set `MAINBRAIN_ROOT` to a real MainBrain checkout to run it from anywhere else. The canon drift gate reads the same variable (or `VCP_CANON_ROOT`, a `canon/canonical` folder) and, when it finds no canon, says SKIPPED on stderr the same way.

**The record starts at adoption.** The entries below are the production deploy the site was serving when this file was adopted on 2026-09-28 and the visible fix that shipped just before it. Earlier deploys are in `git log` and in the Vercel project's deployment list, and are not backfilled here.
